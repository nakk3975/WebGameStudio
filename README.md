# GhostDesk — 가상 컴퓨터 속 추리게임

첨부된 「GhostDesk 웹게임 기획서 v2.0」에 따라 개발한 브라우저 추리게임입니다.
첫 사건은 **03:17에 멈춘 전송**입니다. 설치 없이 웹브라우저에서 기록을 읽고, 보관함을 열고, 증거를 골라 결론을 제출합니다.

## 지금 가능한 것

- 가상 데스크톱: 파일 열기, 창 이동·전환·최소화·최대화·좌우 배치, 작업표시줄.
- 사건 선택 화면에서 서로 다른 다섯 미스터리를 플레이합니다. 사건별 진행을 따로 저장합니다.
- 단서 수집, 추리 노트, 단계별 힌트, 두 결론과 오답 결론에서 조사 재개.
- DOM과 분리된 결정론적 엔진: 논리 타이머, 순서가 고정된 once 규칙, 전파 예산과 롤백.
- IndexedDB 저장, 기존 단일 슬롯의 안전한 전환, JSON 내보내기/복구, 탭 이탈 시 일시정지.
- 로컬 제작기: 샘플 복제, 10개 초안, 파일·단서·퍼즐·대화·규칙·엔딩·가설 폼, React Flow 연결 보기, 실행 취소/다시 실행, 참조 오류 검사, 별도 스냅샷 테스트.
- 원본과 다른 ID로 JSON 가져오기. HTML·외부 URL·잘못된 참조·용량/깊이 초과 검사.

시간은 제작 시 추정치이며 신규 사용자 평가를 거친 수치는 아닙니다. 새 사건마다 별도 자료·대화·단서·힌트·정답/오답 엔딩을 포함합니다.

웹 주소: https://ghostdesk-p24l.onrender.com

Neon DB와 Render API 연결을 완료했습니다. 공개 사건 목록과 버전 패키지를 DB에서 조회합니다. 서버 응답이 늦을 때는 번들 사건으로 바로 플레이할 수 있습니다. 이메일 계정으로 로그인하면 공식 사건 진행·단서·노트를 Neon에 자동 저장하고 다른 기기에서 이어 할 수 있습니다. 비회원 진행과 제작기 초안은 현재 기기에 저장됩니다. 배포 검증 결과는 `docs/DEPLOYMENT.md`에서 확인할 수 있습니다.

배포 전 확인용 `output/GhostDesk_Play.html`은 JS/CSS를 포함한 단일 HTML입니다. 다운로드한 파일을 Chrome/Edge로 열 수 있습니다. 브라우저별 file origin 저장 정책은 다를 수 있으므로 중요한 진행은 JSON으로 내보내세요. Chrome/Edge 실기기에서의 단일 파일 실행은 별도 확인 대상입니다.

조작: 바탕화면에서 파일을 더블클릭하거나 Tab → Enter. 모바일 너비에서는 한 번 눌러 엽니다. Esc는 현재 창을 닫습니다. 창 제목 표시줄 버튼으로 좌우 배치/최대화가 가능합니다.

## 개발 명령

Node 24.19.0 / npm lockfile을 사용합니다.

```sh
npm ci
npm run typecheck
npm test
npm run dev -- --host 0.0.0.0 --port 4173
npm run build
npm run standalone
```

- `apps/ghostdesk`: React/TypeScript/Vite 화면, 샘플 사건, IndexedDB 어댑터
- `packages/engine-ghostdesk`: 외부 I/O 없는 사건 reducer
- `packages/contracts`: Zod 형식 검사, 참조/접근성 검사, 복제
- `tests`: 자동 검증
- `docs/IMPLEMENTATION.md`: 구현 범위, 한계, 후속 단계
- `docs/VERIFICATION.md`: 실제 실행 결과
- `apps/api`: Java 21 / Spring Boot 3.5 / MyBatis 공개 사건·계정 저장 API
- `db/migrations`: 버전 관리하는 Neon PostgreSQL 초기 스키마·샘플
- `render.yaml`: Render 정적 사이트 + 무료 Docker API 배포 설정
- `docs/DEPLOYMENT.md`: 서버 설정과 운영 확인 방법

## 구현 단계

현재 구현 범위는 G0·G1, G2 기본 기능 및 G3의 계정 인증·공식 사건 저장입니다. G2와 G3 전체를 완료한 상태는 아닙니다. 구현 여부와 검증 범위를 구분하며, 세부 한계는 [IMPLEMENTATION.md](docs/IMPLEMENTATION.md), 실행 근거는 [VERIFICATION.md](docs/VERIFICATION.md)에 기록했습니다.

| 단계 | 구현 상태 | 현재 범위와 남은 기능 |
|---|---|---|
| G0 게임 진행 | 구현 | 결정론적 엔진, 가상 데스크톱, 퍼즐·단서·힌트·결말과 공식 다섯 사건. 신규 이용자의 난이도 평가는 별도 검증 대상입니다. |
| G1 로컬 기능 | 구현 | IndexedDB 사건별 저장, 진행 파일 내보내기/복구, 일시정지·복원. 실제 단말의 저장 제한과 전체 브라우저 시나리오는 검증이 남아 있습니다. |
| G2 제작기 | 기본 기능 구현 | 로컬 초안·복제·폼 편집·보조 그래프·참조 검사·스냅샷 테스트. 재접속 후 Undo/Redo 이력 복구, 그래프 직접 연결 편집 등은 미구현입니다. |
| G3 인증·개인 데이터·발행·초대 | 부분 구현 | Neon Auth 이메일·비밀번호 가입/로그인/로그아웃, 공식 다섯 사건의 진행·단서·노트 계정 저장/복원, 비회원 기록 가져오기, 계정별 캐시, 오프라인 재시도와 revision 409 충돌 백업/선택을 구현했습니다. 개인 제작기 초안·사용자 제작 사건의 서버 동기화, 제작기 서버 발행·초대는 미구현입니다. |
| G4 커뮤니티·운영 | 미구현 | 사용자 제작 사건의 커뮤니티 목록 화면·신고·운영 도구. 현재 공개 공식 사건 카탈로그 API는 커뮤니티 기능 완료를 뜻하지 않습니다. |

Spring Boot/MyBatis API는 공개 사건 목록·버전 패키지 조회와 인증된 계정의 공식 사건 저장 조회/갱신을 제공합니다. 웹은 서버 패키지를 검증해 가져오며, 응답이 늦거나 없으면 번들 사건으로 바로 플레이할 수 있습니다. 비회원 진행·제작기 초안·사용자 제작 사건·설정·단일 HTML은 기기 저장을 사용합니다.

**계정 기능의 검증 범위:** 2026-09-28 기록에는 실제 인증 API와 독립 HTTP 쿠키 세션을 통한 공식 다섯 사건 저장/복원, 계정 분리, 미인증/위조 토큰 거부, 오래된 revision의 409 응답이 있습니다. 자동 검사에는 오프라인 큐, 충돌 백업/선택과 계정별 캐시 분리가 포함됩니다. 로그인 폼 표시 확인과 React/jsdom 검사는 실제 로그인 UI 왕복 검증과 구분합니다. 자격 증명을 화면에 입력해 새 조사→저장→브라우저 종료 또는 세션 재생성→재로그인→복원하는 브라우저 E2E, 실제 휴대전화 간 이어하기·iPhone Safari, 실제 이메일 수신·비밀번호 재설정 완료는 검증이 남아 있습니다. 이번 문서 정리는 해당 검증을 새로 수행했다는 의미가 아닙니다.

가입은 이메일·비밀번호 방식이며 별도 이메일 주소 인증 절차를 요구하지 않습니다. 이메일 코드 방식의 비밀번호 재설정 UI는 구현돼 있지만 실제 수신·완료 검증과는 구분합니다.

이 버전은 소스 번들에 정답이 있습니다. 경쟁/상품용 판정이나 비밀 콘텐츠 배포에 사용할 수 없습니다. 비회원 로컬 저장은 백업이나 기기 간 동기화가 아닙니다. 계정 모드에서는 기기를 바꾸기 전 “계정에 저장됨”을 확인하세요.

## 서버 실행

Java 21과 Maven 3.9가 필요합니다. `.env.example`에 적힌 서버 변수를 환경에 주입합니다.

```sh
mvn -s apps/api/maven-settings.xml -f apps/api/pom.xml verify
java -jar apps/api/target/ghostdesk-api.jar
```

- `GET /health/live`: DB를 깨우지 않는 프로세스 상태
- `GET /health/ready`: 실제 DB·공개 사건 조회 확인
- `GET /api/v1/ghostdesk/catalog`: 최대 50개 공개 사건
- `GET /api/v1/ghostdesk/versions/demo-0317-v1/package`: 샘플 사건

이 저장소는 공개입니다. DB 비밀번호·개인 진행·초안은 커밋하지 않습니다.

## 계정으로 이어 하기

1. 사이트 상단 **로그인 / 회원가입**에서 이메일과 8자 이상 비밀번호만 입력합니다. 이름 입력이나 별도 이메일 인증 없이 바로 시작합니다.
2. 기존 비회원 기록은 플레이했던 기기에서 로그인한 다음 **비회원 진행 가져오기**를 누릅니다. 계정에 이미 있는 사건은 덮어쓰지 않습니다.
3. **계정에 저장됨**을 확인하고, 다른 기기에서 같은 계정으로 로그인합니다. 사건을 선택하고 **이어서 조사**를 누릅니다.
4. 동시에 다른 기기에서 수정한 기록은 홈에서 어느 쪽을 이어갈지 선택합니다. 선택 전 두 기록을 현재 기기에 백업하며 JSON 내보내기도 지원합니다.

공식 5개 사건의 진행·단서·노트가 계정에 저장됩니다. 사용자 제작 사건, 제작기 초안, 설정, 내려받은 단일 HTML은 기기 저장을 사용합니다. 네트워크가 끊기면 현재 계정의 기기 저장에 보관하고 재연결 시 재시도합니다. 저장 확인 전 브라우저 데이터를 삭제하면 미전송 진행은 잃을 수 있습니다. 비밀번호 재설정은 이메일 코드 방식입니다.
