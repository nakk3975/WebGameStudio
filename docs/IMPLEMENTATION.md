## 범위

기획서 04장 G0→G1→G2에 따라 게임 한 편을 먼저 구성했다. React + TypeScript + Vite, Zod, React Flow를 사용한다. 공개 사건 조회를 위해 Java API와 Neon을 연결했다. G3 중 Neon Auth 이메일·비밀번호 인증과 공식 다섯 사건의 계정 저장·복원은 구현했다. 제작기 초안·사용자 제작 사건의 서버 동기화, 제작기 서버 발행·초대는 후속 범위다. 서버가 없어도 로컬 게임이 끝까지 돌아간다. 인게임 AI/API, 게임 내 외부 파일·실제 메일·터미널 연결, 유료 서비스, 추적 스크립트가 없다.

## 단계별 상태

- G0 게임 진행과 G1 로컬 저장 기능은 구현했다. 신규 이용자 평가와 실제 단말·저장 제한 검증을 모두 완료했다는 의미는 아니다.
- G2는 로컬 제작기 기본 기능까지 구현했다. 남은 차이는 아래 절에 기록한다.
- G3는 계정 인증과 공식 사건 진행·단서·노트 동기화까지 부분 구현했다. 제작기 초안·사용자 제작 사건 서버 동기화, 서버 발행·초대는 미구현이다.
- G4 사용자 제작 사건 커뮤니티 목록 화면·신고·운영 도구는 미구현이다. 공개 공식 사건 카탈로그 API와 구분한다.

## G2의 남은 차이

- 여러 초안은 저장되지만 Undo/Redo 이력은 제작기 세션 내 100개만 유지한다. 기획의 재접속 이력 복구는 후속 작업이다.
- 증거 보드는 단서와 메모를 제공한다. 사용자가 그리는 증거 간 연결선은 후속 작업이다.
- 공식 사건에는 번들 사진 자료와 재현 영상이 추가돼 있다. 사용자 제작기의 이미지 업로드·에셋 관리 기능 완료를 뜻하지 않는다. 자료별 구현·검증은 VERIFICATION.md와 ALL_CASE_EVIDENCE_AUDIT.md를 참고한다.
- 파일/메신저 창은 가상 데이터만 사용한다. 모든 CHAT_LINK는 사건의 공통 대화를 표시한다.
- 시간대·잠금 안내·목표 일부는 샘플 중심 문구다. 다른 장르 사건을 넓게 제작하려면 안내 문구도 패키지화해야 한다.
- 조건 그래프는 설명/이동 도구다. NOT/플래그 모순 등 모든 불가능한 사건을 정적으로 증명하지 않는다. 경고를 표시하고 직접 플레이해야 한다.
- 네이티브 경로 대신 `#/play/...`, `#/studio` 표시를 사용한다. 직접 링크 라우팅/개별 사건 상세 페이지는 서버 단계에서 구성한다.
- 폴더 이동은 드롭다운이다. 드래그 파일트리, 앱별 소리·볼륨, 별도 파일 검색은 없다.
- 다른 탭 편집은 Web Locks API를 지원할 때 읽기 전용으로 제한한다. 지원하지 않는 환경에서는 경고한다. 강제 편집 복사본 버튼은 후속 작업이다.

## 저장

정상 사건 상태만 IndexedDB에 저장한다. 정상 진행 JSON에는 원본 사건 패키지, caseVersionId, schema/engine version, 논리 시각, 단서/해결/읽음/규칙/타이머, 메모, 결론 전 체크포인트가 포함된다. ERROR 상태는 직전 정상 슬롯을 덮어쓰지 않는다. 저장 표시를 실제 트랜잭션 완료 이후 바꾼다.

탭이 숨겨지거나 초점을 잃으면 PAUSED. 복귀 후 사용자가 재개해야 한다. TICK은 최대 1초만 허용하며 벽시계 차이를 누적하지 않는다. 세이브 복원도 PAUSED에서 시작한다. 이는 백그라운드 catch-up을 막기 위한 선택이다.

제작기 테스트는 패키지를 복제하고 revision이 붙은 versionId를 사용한다. 테스트 플레이는 정식 플레이 슬롯에 쓰지 않는다. 규칙은 우선순위와 ASCII ID로 정렬되며 단계별 동시 조건 스냅샷에 따라 실행된다.

## 0.2 서버 연결

2026-09-28 사용자가 공개 GitHub 저장소·커밋·Neon·Render 생성을 승인했다. 새 WebGameStudio 저장소와 WebGameStudio-GhostDesk DB를 만들고, 공개 사건 카탈로그와 버전 패키지 조회 API를 추가했다. 초기 공개 조회 API는 SELECT 권한의 ghostdesk_app 역할을 사용했으며, 프런트에는 DB 자격 증명을 포함하지 않는다. 별도 DB 브랜치에서 초기 마이그레이션을 검증했다.

공개 사건 패키지 조회는 읽기 전용이다. 이후 V003 계정 저장 마이그레이션에서 ghostdesk_app에 user_saves의 SELECT/INSERT/UPDATE 권한을 추가하고 RLS로 계정별 접근을 제한했다. 현재 서버 전체가 SELECT만 가능한 것은 아니다. 자세한 배포 구성은 DEPLOYMENT.md를 참고한다.

## G3 계정 기능과 남은 범위

- 구현: Neon Auth 이메일·비밀번호 회원가입/로그인/로그아웃, 세션·토큰 연동, 공식 다섯 사건의 진행·단서·노트 자동 저장/복원과 기기 간 이어하기 경로, 비회원 기록 가져오기(계정의 기존 사건은 덮어쓰지 않음).
- 구현: 계정별 로컬 캐시, 오프라인 업로드 큐·재시도, 저장 revision 경합 시 409 처리와 양쪽 기록의 기기 백업/선택. 서버 저장은 `GET /api/v1/ghostdesk/saves`, `PUT /api/v1/ghostdesk/saves/{caseId}`를 사용하며 공개 버전 패키지와 일치하는 사건만 받는다.
- 저장 제외: 사용자 제작 사건·제작기 초안·설정·단일 HTML은 기기 저장이다. 공식 사건 진행 동기화가 개인 제작기 초안 동기화까지 제공하는 것은 아니다.
- 미구현: 개인 초안/사용자 제작 사건 서버 동기화, mutation receipt, draft revision 409, 제작기의 immutable version 서버 발행, 초대·협업 권한, 운영 백업. 플레이 저장의 revision 409와 제작기 초안 revision 409는 별개다.
- 가입 시 별도 이메일 주소 인증을 요구하지 않는다. 비밀번호 재설정은 이메일 코드 UI를 구현했으며 실제 이메일 수신·재설정 완료는 미검증이다.

### 계정 기능의 검증 근거와 한계

[VERIFICATION.md의 0.3 계정 저장 검증](VERIFICATION.md#03-계정-저장-검증--2026-09-28)에 자동 검사, 검증 DB의 RLS 검사 및 운영 API 검증을 기록했다. 독립 HTTP 쿠키 세션으로 실제 가입/로그인/세션/토큰/로그아웃, 공식 다섯 사건 PUT 후 별도 세션 GET 복원, 다른 계정 분리, 미인증·위조 토큰 거부, 오래된 revision 409와 최신 노트 보존을 확인했다. 자동 검사에는 오프라인 큐·충돌 백업/선택·계정별 캐시 분리가 포함된다.

운영 Chrome에서 로그인 폼 표시·버튼 활성화는 확인했지만 실제 자격 증명 입력은 UI에서 수행하지 않았다. 로그인한 React 화면으로 새 조사→저장→브라우저 종료 또는 세션 재생성→재로그인→복원을 끝까지 조작하는 브라우저 E2E, 실제 휴대전화 간 이어하기·iPhone Safari, 실제 이메일 복구 완료는 검증이 남아 있다. React/jsdom 회귀 검사와 독립 HTTP 세션 검사는 이를 대신하지 않는다. 후속 자료 검증에서도 실제 계정 저장 왕복을 완료했다고 기록하지 않았다(ALL_CASE_EVIDENCE_AUDIT.md 참조).

2026-10-08 갱신은 현재 코드와 누적 검증 기록을 대조한 문서 정리다. 새 운영 인증·저장 실험이나 브라우저 E2E를 수행했다는 의미는 아니다.

## 재검증 보완

게임·제작기 화면 이동은 저장 완료를 기다리고 실패 시 현재 화면을 유지한다. 제작기 테스트 동안 초안 선택과 Undo/Redo를 유지하며 Web Locks도 계속 보유한다. 엔진과 UI가 숨김·상위 폴더 잠금 접근 검사를 공유한다. ID는 프로토타입과 분리된 사전에 보관하고, 복제 ID에는 고유 순번을 포함한다.

웹 제작기는 지연 로딩한다. `npm run standalone`은 별도의 단일 번들을 만들어 `output/GhostDesk_Play.html`을 생성하므로 웹 배포용 dist를 변경하지 않는다. CI에서도 이 경로를 검사한다.
