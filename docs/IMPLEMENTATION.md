## G2의 남은 차이

- 여러 초안은 저장되지만 Undo/Redo 이력은 제작기 세션 내 100개만 유지한다. 기획의 재접속 이력 복구는 후속 작업이다.
- 증거 보드는 단서와 메모를 제공한다. 사용자가 그리는 증거 간 연결선은 후속 작업이다.
- 이미지 에셋은 정확한 두 시각을 표시하는 번들 컴포넌트 하나다. 실제 사진, 사용자 업로드, 효과음은 넣지 않았다.
- 파일/메신저 창은 가상 데이터만 사용한다. 모든 CHAT_LINK는 사건의 공통 대화를 표시한다.
- 시간대·잠금 안내·목표 일부는 샘플 중심 문구다. 다른 장르 사건을 넓게 제작하려면 안내 문구도 패키지화해야 한다.
- 조건 그래프는 설명/이동 도구다. NOT/플래그 모순 등 모든 불가능한 사건을 정적으로 증명하지 않는다. 경고를 표시하고 직접 플레이해야 한다.
- 네이티브 경로 대신 `#/play/...`, `#/studio` 표시를 사용한다. 직접 링크 라우팅/개별 사건 상세 페이지는 서버 단계에서 구성한다.
- 폴더 이동은 드롭다운이다. 드래그 파일트리, 앱별 소리·볼륨, 별도 파일 검색은 없다.
- 다른 탭 편집은 Web Locks API를 지원할 때 읽기 전용으로 제한한다. 지원하지 않는 환경에서는 경고한다. 강제 편집 복사본 버튼은 후속 작업이다.

## 저장

정상 사건 상태만 IndexedDB에 저장한다. 정상 진행 JSON에는 원본 사건 패키지, caseVersionId, schema/engine version, 논리 시각, 단서/해결/읽음/규칙/타이머, 메모, 결론 전 체크포인트가 포함된다. ERROR 상태는 직전 정상 슬롯을 덮어쓰지 않는다. 저장 표시를 실제 트랜잭션 완료 이후 바꾼다.

탭이 숨겨지거나 초점을 잃으면 PAUSED. 복귀 후 사용자가 재개해야 한다. TICK은 최대 1초만 허용하며 벽시계 차이를 누적하지 않는다. 세이브 복원도 PAUSED에서 시작한다. 이는 백그라운드 catch-up을 막기 위한 선택이다.

제작기 테스트는 패키지를 복제하고 revision이 붙은 versionId를 사용한다. 테스트 플레이는 정식 플레이 슬롯에 쓰지 않는다. 규칙은 우선순위와 ASCII ID로 정렬되며 단계별 동시 조건 스냅샷에 따라 실행된다.

## 0.2 서버 연결

2026-09-28 사용자가 공개 GitHub 저장소·커밋·Neon·Render 생성을 승인했다. 새 WebGameStudio 저장소와 WebGameStudio-GhostDesk DB를 만들고, 공개 사건 카탈로그와 버전 패키지 조회 API를 추가했다. 서버는 SELECT만 가능한 ghostdesk_app 역할을 사용하며, 프런트에는 DB 자격 증명을 포함하지 않는다. 별도 DB 브랜치에서 초기 마이그레이션을 검증했다.

앱 계정 인증, 개인 초안·플레이 저장의 서버 동기화, mutation receipt, draft revision 409, 제작기의 immutable version 발행, 초대·두 사용자 권한 검사는 후속 작업이다. 자세한 배포 구성은 DEPLOYMENT.md를 참고한다.

## 재검증 보완

게임·제작기 화면 이동은 저장 완료를 기다리고 실패 시 현재 화면을 유지한다. 제작기 테스트 동안 초안 선택과 Undo/Redo를 유지하며 Web Locks도 계속 보유한다. 엔진과 UI가 숨김·상위 폴더 잠금 접근 검사를 공유한다. ID는 프로토타입과 분리된 사전에 보관하고, 복제 ID에는 고유 순번을 포함한다.

웹 제작기는 지연 로딩한다. `npm run standalone`은 별도의 단일 번들을 만들어 `output/GhostDesk_Play.html`을 생성하므로 웹 배포용 dist를 변경하지 않는다. CI에서도 이 경로를 검사한다.
