# 기록 대조와 마지막 해결 — v6

2026-09-30. 다섯 테마의 큰 설정과 기존 사진·영상의 사실 관계를 유지하면서
각 10개 문제를 다시 구성했다. 기존 v1–v5의 24개 발행본은 수정하지 않는다.

## 플레이 흐름

- 시작 화면 설명과 첫 인계 메모가 플레이어의 역할, 의뢰 이유, 해결할 일을 설명한다.
- 모든 폴더는 일반 업무명이다. 50개 암호 규칙은 잠금 전에 접근 가능한 원본 기록에 있다.
  잠금 화면에 자료 목록이나 답을 노출하지 않는다. 선택형 힌트는 규칙→추론→정답 순서다.
- A/B/C 선택과 선택지 순열 입력은 새 판에서 제거했다. 시간을 보정하거나 서로 다른
  기록의 조건을 대조해 직접 입력한다. 마지막 문제는 이미 사용한 원본 3개 이상을 재사용한다.
- 9번째 폴더까지 열어도 사건은 RUNNING이다. 10번째 폴더의 **해결 승인**이 성공해야
  기존 END_CASE 효과로 사건이 끝난다. 중간 결론 선택이나 부분 답으로 우회할 수 없다.
- 엔진·저장 스키마 변경은 없다. 기존 저장은 원래 발행본으로 이어지고,
  ‘새 조사 시작’은 새 판을 시작하면서 종전 진행을 기기에 별도로 보관한다.

## 일관성 점검

후반 표 이미지의 값은 v5와 동일하며 새 계산이나 승인 규칙은 문서에 추가했다.
공연 조명 영상은 시간 간격을 줄인 재현으로 유지하고 시각 계산에는 제어기 원본을 쓴다.

플레이어가 마지막 암호를 제출한 뒤에만 결말에서 완료된다.

## 검증과 배포

- 타입 검사, 287개 테스트(19개 파일), 프로덕션 빌드 통과.
- 독립적으로 검토한 50개 답으로 엔진과 실제 React 입력 폼을 각각 완주.
- 규칙과 모든 근거의 접근성, 잘못된/부분 답, 미래 폴더와 기존 결론 경로 우회,
  자동 다음 폴더, 최종 엔딩, 새로고침 시 PAUSED와 logicalMs 유지 확인.
- 기존 v5의 관찰·선택 컨트롤 완주 검사를 그대로 보존하고 대상을 v5로 명시했다.
- 실제 로그인 계정 세션에서의 저장 왕복은 별도 미검증이다. 계정 저장 경쟁 회귀는
  기존 테스트 더블로 확인하며 새 발행본과 API의 패키지 일치를 별도로 검증한다.
- 브라우저 화면 검증은 배포 후 별도 기록한다. 난이도/예상 플레이 시간은 신규 사용자
  플레이테스트로 확정한 수치가 아니다.

생성 원본: `scripts/resolution-cases.py`. 검토용 풀이:
`tests/fixtures/resolution-walkthrough.json`, 독립 제출 답:
`tests/fixtures/resolution-solutions.ts`.

V008은 사건 5행만 추가한다. 테이블 구조·권한·사용자 저장을 변경하지 않는다.
