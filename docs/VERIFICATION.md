브라우저 초기 연결에서 지연이 있었으며 개발 서버 옵션을 정리한 뒤 연결됐다. 로컬 file: URL은 테스트 브라우저 정책상 열 수 없어 HTTP 미리보기를 사용했다. 이는 단일 HTML 파일을 Windows Chrome/Edge에서 직접 실행한 검증과는 다르다.

검증 중 발견/수정: 논리 시간 TICK으로 인해 저장 debounce가 반복 취소되는 문제를 실제 변경 키와 타이머 주기 저장으로 분리; 360px 첫 화면의 버튼/상단 폭 초과 수정; HTTP 환경 제작기에서 UUID API 대신 getRandomValues 사용; 복제된 사건의 목표 안내가 원본 ID에 의존하지 않도록 수정.

## 재검증 및 수정 / 2026-09-28

- 자동 검사: 타입 검사, 프런트 테스트 51개(기존 37 + 회귀 14), 웹 빌드 통과. Java 21 API 테스트 6개 및 Maven verify 통과.
- 제작기에서 두 번째 초안을 수정한 뒤 테스트를 끝내면 첫 번째 초안으로 돌아가고 Undo가 사라지는 문제를 기존 운영 화면에서 재현했다. 제작기를 테스트 중 유지하여 초안 선택·카테고리·Undo/Redo·테스트 revision을 보존한다.
- 숨긴 파일/잠긴 상위 폴더에 대한 UI 접근 검사가 엔진과 달랐다. 창 열기와 렌더링에 공통 접근 검사를 적용하고 접근할 수 없는 퍼즐 해결도 거부한다. 증거 보드에서 접근 가능한 원본을 선택한다. 시스템 창 ID는 파일 ID와 충돌하지 않도록 분리했다.
- 화면을 나가기 전에 IndexedDB 트랜잭션 완료를 기다린다. 저장에 실패하면 화면 이동을 멈추고 재시도·내보내기 안내를 제공한다. 저장 요청의 복사본과 순서를 보호하는 큐를 적용했다. 지연 완료, 연속 쓰기, 저장 실패 후 재시도를 단위 검사했다. 실제 브라우저 quota 강제 실패는 미검증이다.
- 제작기는 탭 잠금 결과를 확인한 뒤 초안을 읽고 편집·자동 저장을 허용한다. 읽기 전용 안내가 저장 메시지에 덮이지 않는다. 로컬 HTTP에서는 Web Locks가 없어 동시 편집 경고를 확인했다. 운영 HTTPS의 두 탭 검증은 배포 후 별도 기록한다.
- constructor/__proto__/toString ID의 플래그·타이머·암호·힌트가 정상 작동하고 JSON 복원 뒤에도 유지되도록 사전 객체를 정규화했다. 긴 ID의 앞부분이 같을 때 복제 ID가 겹치는 문제를 수정했다. 잘못된 체크포인트 false/0/빈 문자열/누락은 가져오기에서 거부한다.
- 사용자 사건의 잠금 안내가 샘플의 시각 문제로 고정되지 않도록 퍼즐 제목을 표시한다. 최대 길이 versionId에서도 테스트 revision을 포함해 길이 제한을 지킨다.
- 제작기는 필요할 때 불러온다. 동일 작업 빌드 기준 초기 JS는 567.22 kB에서 368.64 kB로 약 35% 감소( gzip 177.21 → 113.21 kB). 실제 사용자 지연시간 측정은 아니다.
- 단일 HTML은 별도 단일 번들로 만들어 웹의 코드 분할과 호환시켰다. 647,538 bytes 생성 성공. CI에 단일 HTML 생성도 추가했다.
